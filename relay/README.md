# Relay

The server for Correspondence Games (ADR 0002): a Cloudflare Worker that routes each Game to its
own SQLite-backed Durable Object. It keeps each Game's Game Events in order, stamps them with its
own time, and passes them between the two Seats. It has no chess logic. The wire protocol, and the
contract the Kotlin client implements, is [`docs/protocol.md`](../docs/protocol.md).

| File | What it holds |
|---|---|
| `src/index.ts` | The Worker: routing, hashing secrets, the redeem rate limit, the batched sync. |
| `src/game.ts` | `CorrespondenceGame`, the Durable Object: Seats, invite, log, retention alarm, presence. |
| `src/protocol.ts` | Constants, shapes, validation and error codes from the protocol. |
| `src/secrets.ts` | Seat secrets, join tokens and Invite Codes. |
| `test/` | Vitest suites that run inside workerd through `@cloudflare/vitest-pool-workers`. |
| `wrangler.jsonc` | The Worker, the Durable Object binding and SQLite migration, the rate limit. |
| `worker-configuration.d.ts` | `Env`, generated by `npm run types` from `wrangler.jsonc`. |

## Local development

Needs Node 22 or later (wrangler 4 refuses older versions) and npm. No Cloudflare account.

```sh
cd relay
npm ci
npm test            # 101 tests in workerd, fully local
npm run typecheck
npm run dev         # http://localhost:8787, local Durable Objects under .wrangler/
```

`npm run check` runs the typecheck, the tests, and `wrangler deploy --dry-run`, which bundles the
Worker without contacting Cloudflare. Run `npm run types` after changing a binding in
`wrangler.jsonc`.

Tests move clocks by rewriting a Game's stored metadata (`patchMeta` in `test/helpers.ts`) and
fire alarms with `runDurableObjectAlarm`, so nothing waits for real time. Local Miniflare emulates
the rate-limiting binding, so the per-IP limit is tested too. What the tests can't show: the
production limiter is per Cloudflare location and eventually consistent, so its real limit is
approximate, and hibernation eviction of an idle Durable Object with open sockets is not exercised
(attachments are, since presence reads them).

## End-to-end test with the Kotlin client

`RelayEndToEndTest` (tool/src/test/.../relay/) drives two phones' sync engines over OkHttp against
the local Worker. It is skipped unless the Worker's URL is given, and never runs in CI:

```sh
cd relay && npm run dev -- --port 8787 --ip 127.0.0.1     # leave it running
# from the repo root, in another shell:
mise exec -- ./gradlew :tool:testDebugUnitTest --tests '*RelayEndToEndTest' -Drelay.e2e=http://127.0.0.1:8787
```

The client allows plain HTTP only to 127.0.0.1 or localhost; everything else must be HTTPS.

## Deploying

The Relay's address is `https://chess-relay.yarosz.com` (decision log W11). The Tool ships with it
(`RelayConfig.URL`), so it doesn't change once a release is out. The maintainer deploys it, from
the maintainer's Cloudflare account that holds the `yarosz.com` zone. Not deployed yet.

`npx wrangler deploy` uploads the Worker and its Durable Object migration only. The custom domain
`chess-relay.yarosz.com` is bound to the `chess-relay` Worker separately, after the first deploy,
by the maintainer's infrastructure code, so wrangler never creates DNS and `wrangler.jsonc` has no
`routes`. `workers_dev` is `false`, so the Worker has no second address on workers.dev: there is one
public address, the one the Tool ships.

### Prerequisites

- The Cloudflare account that holds the `yarosz.com` zone (a custom domain must be on a zone in the
  Worker's own account). SQLite-backed Durable Objects and the rate-limiting binding are available
  on the Workers Free plan; check the current limits (the decision log's C7 assumes about 100,000
  requests a day, which holds only while polling stays small).
- Credentials for wrangler, one of:
  - `npx wrangler login` (browser OAuth), or
  - `CLOUDFLARE_API_TOKEN` (a token from the "Edit Cloudflare Workers" template, scoped to that one
    account) plus `CLOUDFLARE_ACCOUNT_ID`.
- No Worker secrets. The Relay holds none: seat secrets are generated per Game and stored only as
  SHA-256 digests.
- `namespace_id` of the `REDEEM_LIMITER` binding (`"1001"`) must be unique among the rate limiters
  in the account; change it if another Worker already uses it.

### Commands

```sh
cd relay
npm ci
npm run check                       # typecheck, tests, dry-run bundle
npx wrangler login                  # or export CLOUDFLARE_API_TOKEN and CLOUDFLARE_ACCOUNT_ID
npx wrangler whoami                 # confirm the account before deploying
npx wrangler deploy                 # applies migration v1 (new_sqlite_classes) on the first deploy
# then bind the custom domain chess-relay.yarosz.com to the chess-relay Worker (outside this repo)
curl https://chess-relay.yarosz.com/health
# expect: {"status":"ok","protocol":"1.0","majors":[1]}
```

After the first deploy, in the Cloudflare dashboard, confirm that Workers Logs, Logpush and Tail
are off for `chess-relay` (C6: the Relay logs nothing). `observability.enabled: false` in
`wrangler.jsonc` covers Workers Logs only.

### Changing the Durable Object later

`migrations` in `wrangler.jsonc` is append-only. Never edit or remove tag `v1`: a rename or delete
of `CorrespondenceGame` needs a new tag, and deleting the class deletes every Game. A new protocol
major must keep the old one served while any live Game is pinned to it (E9): add it to `MAJORS` in
`src/protocol.ts`, never replace it.
